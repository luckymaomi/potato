# Plan

根目录 `plan.md` 是当前任务的单文件执行合同，不是产品 spec，也不是历史日志。

## 启用后

1. 读取 `AGENTS.md`、当前 spec、项目开发 skill 和已有计划。
2. 确认已有 `plan.md` 是否属于当前任务；不属于时先保存其事实，不混写两个目标。
3. 从 `plan.example.md` 建立需求、当前事实、失败证据、目标、不做范围、设计、任务、验证和收口。
4. 实施前写清事实 owner 和完整影响面；新证据推翻设计时先更新计划。
5. checklist 只反映真实完成状态，不能用勾选代替验证。

## 完成

所有任务、验证、未验证项、风险、commit 和 push 状态必须回填；未完成范围不能包装成“后续优化”。
