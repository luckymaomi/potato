# potato Development

## 开始前

1. 读取根目录 `AGENTS.md`、当前 spec、README 和命中的业务 skill。
2. 检查分支、Git 状态、无关改动、入口、依赖、配置和验证命令。
3. 从用户入口追踪输入、规则、状态、持久化、输出、错误和恢复。
4. 找到本次变化涉及的事实 owner、直接消费者、测试和文档。
5. 若任务跨模块、涉及迁移、外部副作用或恢复，读取 plan skill 并维护根 `plan.md`。

## 实现

- 先证明问题和目标，再修改；用户建议不是自动正确的实现方案。
- 采用范围明确的补丁，逐块核对；禁止无审查机械替换。
- 一个事实只有一个 owner；展示层、handler、adapter 和测试不得重新计算 owner 已拥有的事实。
- 当前事实推翻旧结构时按 `AGENTS.md` 的断裂式变更或前向迁移规则处理。
- 一个职责完整模块内同步代码、测试、spec、README、配置和生成物。

## 验证与沉淀

- 定向测试证明当前修改，完整验证证明没有破坏项目其余主干。
- 外部系统按证据闸门做修改前探针和修改后真实复验；人工审美或业务判断交给 owner。
- 重要探索写 history；可复用方法提炼到 skill；当前产品事实写 spec；跨项目长期纪律才写 AGENTS。

## 交付

- 完成职责完整模块后检查差异、敏感信息、验证和文档，再按授权 commit/push。
- 回复只报告完成事实、实际验证、未验证项、剩余风险和外部状态。
