# Validation and Delivery

## 证据分层

- 定向测试证明本次规则，全量 test/lint/typecheck/build 证明主干未被明显破坏。
- 浏览器交互、真实供应商、真实媒体和最终审美分别报告；任何一层都不能用另一层绿灯替代。
- 真实模型内容只检查流程契约：文本非空、提取有结果、媒体真实落盘。不得断言随机内容字面量或固定数量，除非数量本身是产品输入。

## 外部验收

- 未获得当次授权时，不调用供应商、不运行真实 Demo、不清理 `backend/data`。
- 初始化脚本只初始化；真实工作流只能从 owner 指定入口启动。
- 429 按 Provider 合同有界重试；耗尽或硬错误如实失败，禁止 Mock 或占位文件顶替。

## 交付

1. 检查差异、未跟踪文件、敏感信息、生成物和 `git diff --check`。
2. 完成职责完整模块后，以简体中文一句话提交；只有 owner 当次明确授权才 push。
3. 收尾分开列出完成事实、实际验证、未执行的人工/外部验收、剩余风险和 commit/push 状态。
