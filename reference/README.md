## 画布稳定性与选择显示专项调研

本节记录 2026-09-17 对点击白屏的根因核验。owner 随后明确要求不再等待 n8n 克隆，因此本节不把未完成的 n8n 下载当作证据，结论只采用 React Flow 官方源码与本地 ComfyUI frontend。

### 已核验的成熟做法

- React Flow 官方 `StoreUpdater` 以引用相等判断受控 `nodes/edges` 是否变化；引用变化就调用内部 `setNodes/setEdges`。因此在组件渲染体内反复 `filter/map` 受控图，会把纯显示计算伪装成图数据变化。官方受控示例直接把状态数组交给 `<ReactFlow>`，只在真实 change handler 中产生下一版数组。
- React Flow 的内置贝塞尔边类型名是 `default`，不存在内置 `bezier` 类型；未知类型会触发 error 011 后回退。官方允许以组件外稳定 `edgeTypes` 映射覆盖 `default` 渲染器，并使用 `BaseEdge + getBezierPath` 增加纯显示行为。
- React Flow 官方错误 002 明确要求 `nodeTypes/edgeTypes` 定义在组件外或 memoize，防止每次渲染更换组件类型。当前实现把两套映射固定在模块级。
- ComfyUI frontend 以 `selectedItems` 保存真实选择，以 `highlighted_links` 保存随选择重算的连线显示状态；选择、连线高亮和图文档是不同事实。取消选择会清理高亮，不会为此派生或替换整张图。

### 对本项目的采用边界

- 删除资产折叠和 `visibleAssetGraph`，React Flow 只接收 Zustand 原始 `nodes/edges`。
- 直接关联高亮只 memoize 节点/边 ID 集合；自定义节点和默认边渲染器读取集合加 class，不改 `selected`、不改数组、不写快照。
- 旧快照中的 `bezier` 在读取时统一规范为 `default`；新建和模板边只写 `default`，不保留双轨类型。
- 不引入 ComfyUI 的 LiteGraph 状态机，也不复制其实现；只采用“业务选择与显示高亮分离”的职责边界。

## 节点插件与自治上下文专项调研

本节记录 2026-09-17 在进入产品重构前完成的静态研究。结论只来自上述固定提交及当前仓库，不代表已经完成产品实现或真实供应商验收。

### 已核验的成熟做法

- tldraw Image Pipeline 的 `NodeDefinition` 集中拥有稳定类型、校验器、标题与分类、默认数据、输入输出端口、输出描述、执行函数和 UI 组件；注册表再投影到创建、渲染和执行入口。执行图只解析节点声明过的端口，不按标题、位置或相邻节点类型猜输入。
- ComfyUI frontend 的节点定义由 `/object_info` 提供，集中声明输入、输出、名称、说明、分类、模块及实验/废弃状态；菜单、搜索、控件与注册消费同一定义。资产、队列、执行状态和执行错误分别由独立 store 拥有，错误可关联到工作流、节点执行 ID 与 slot，而不是散落在画布组件中。
- AICON 把供应商模型能力放在服务端 catalog，前端只消费当前凭据真正可用的模型；生成 payload 会显式解析 mention/reference，历史结果以 `resource_type + resource_id` 绑定业务资产并允许选择当前版本。这证明模型能力、资产引用和画布显示应各有 owner。
- Huobao Drama 把角色、场景、道具建成项目级实体，以剧集关联表声明本集资产，以 `scene_id`、`storyboard_characters`、`storyboard_props` 声明单个分镜实际出现的资产；上下文工具按项目、剧集、分镜和资产 ID 查询，不依赖画布前驱。生成任务也直接携带 `storyboardId`、`sceneId`、`characterId` 或 `propId`。
- 四个样本共同支持的边界是：节点声明能力和输入输出，拓扑表达调度与数据方向，执行器只解析显式输入；提示词、默认参数与模型能力各自由目录或服务端 catalog 拥有；错误、取消、重试属于执行基础设施而不是节点卡片条件分支。owner 最终选择更强的节点自治：资产仓库保留持久记录与历史职责，但不再成为运行时隐式输入源。

### 不适合直接采用

- tldraw Image Pipeline 和 ComfyUI 主要依赖端口连线传递上下文，缺少短剧领域的项目级资产仓库；本项目采用“面板完整输入 + 连线追加直接结果”，稳定 ID 只负责领域记录与输出归属，不参与生成时暗取输入。
- tldraw 会并行调度可运行分支，且停止主要阻止后续调度；本项目采用 DAG 和拓扑排序，但当前仍串行提交并保留 AbortSignal、任务取消和首次失败终止合同，不复制其并行执行语义。
- ComfyUI 的 V1 到 V2 迁移层服务于已有生态；本项目没有生产数据或外部兼容承诺，本轮直接重建唯一合同，不保留旧快照、旧字段或双轨执行。
- AICON 的通用文本/图片/视频节点和多套 Vue composable 仍未形成短剧生产插件目录；只采用服务端能力 owner、显式引用和资产历史思路，不复制其画布持久化结构。
- Huobao 的部分提取流程使用进程内任务状态，显式 `replace_existing` 还会全量删除既有记录；本项目保留 SQLite 异步任务，并采用稳定 ID 的同步/upsert，避免重试摧毁已经生成的资产媒体与画布引用。

### 对 potato 的结论

- 生产插件目录必须成为节点语义唯一 owner，至少声明稳定角色、材料、生产用途、上下文需求、产出、参数、默认提示词 key、默认生成方式与执行命令构造器；工具栏、节点卡片、检查器、模板和 Demo 只做投影。
- 节点快照只保存稳定角色、插件参数、显式资产引用和运行结果；删除可互相矛盾的 `material`、`purpose`、`assetKind`、`textOperation`，并以结构化 `assetRefs` 替代旧的 `linkedRecordId(s/index)`。
- 资产仓库统一维护项目归属、稳定 ID、分镜关系和生成历史；提取重跑同步已有实体并保留匹配 ID 与媒体结果，不做先删后建。它不向节点生成命令补提示词、参考图或目标 ID。
- 连线保留自由编排并只表达显式数据传递。内置模板和 Demo 使用分层 DAG：逐镜文本和资产图扇入分镜图，分镜图一对一进入镜头视频，全部镜头视频汇入合成。执行器只读取已经完成的直接入边；单节点不遍历或补跑祖先，未完成入边被忽略。
- 当前统一 `ProductionWorkflowService`、错误合同、`CanvasRunSession`、任务取消和供应商重试基础继续作为唯一生产与失败主干，不恢复分散的图片、视频或文本入口。

### 仍未知

- Agnes 当前真实凭据、模型目录与各生成模式在本轮实现完成后是否仍可用，要经过脱敏配置检查和真实请求才能确认；单元测试、Mock 或历史成功不能替代本轮结果。
- 外部供应商是否支持物理撤销仍取决于其协议；本项目能保证停止本地提交、轮询、结果落库和后续节点，不能在未获协议证据时承诺撤回远端计算。
- Agnes 返回媒体的内容类型、长度与下载稳定性仍要在本轮真实验收中核验；实现将以文件签名和受控大小为完成条件，不能把 HTTP 200 单独当作成功。

## 采用的模式

- 选择对象后才出现上下文命令，命令明确作用于“当前节点”或“所选节点”，避免全局工具栏含糊。
- 全局运行采用主按钮加范围菜单；单节点、所选范围、下游分支和整个画布是不同命令，不用一个“运行”承载多种猜测。
- 工作流执行由连线依赖决定，等待上游完成后再执行下游；连接同时承担必要的文本和参考图片输入。
- 默认模板是可恢复的工作区初始状态，不是一次性的教程遮罩；完整 Demo 是幂等入口，不重复制造项目。
- 节点创建后立即选中；编辑区按节点类型显示必要字段；媒体预览、状态、错误和重试都留在节点上下文内。
- 批量执行前显示节点数量，完成后分别报告成功与失败；保存的工作流组具有名称、成员和独立运行入口。
- 项目列表提供搜索和完整管理动作，打开项目由整张卡片承担，编辑、导出、删除作为次级图标命令。
- 模型参数必须跟随具体模型：AICON 把 `aspect_ratios` 放入服务端策划的模型能力目录，前端切换模型时清理无效比例，生成 payload 只提交所选模型支持的值；ComfyUI 也让比例作为具体节点定义的输入。potato 采用相同职责边界，但能力来源是 Agnes 适配器协议或 PearAPI 实时丰富目录。
- 凭据可用模型与公共丰富元数据必须求交集：只展示当前 Key 真正可用的模型，再补充模式、参考图上限和比例；公共目录故障时保留可用模型身份，但把未知能力明确标为未知。
- Huobao 在项目创建时固定 16:9/9:16，适合单一成片规格；potato 同一画布允许不同模型和媒体节点，因此比例保存在节点并由后端逐任务校验，项目比例只作为新节点默认值。
- 保存链路以 `C:\Users\Administrator\Desktop\repository\mo` 为主要本地蓝本：不可变快照、防抖合并、单写 Promise、expected revision、明确 dirty/error/conflict 和离开保护是可复用原则；其 IndexedDB、Web Locks 与 BroadcastChannel 服务于纯前端本地库，不复制到 Node/SQLite 架构。
- AICON 的节点级 300ms 防抖和“生成前先保存”说明高频编辑与执行边界应分开；但它的自动保存错误只写控制台且没有版本冲突保护，因此 potato 只吸收交互节奏，不采用其完整保存合同。
- tldraw 将 document 与每个标签页的 camera/selection/session 分离；potato 同样只保存画布业务文档，不保存 React Flow 选择态。ComfyUI 的文档架构记录强调保存只能确认请求捕获的 revision，保存期间的新修改必须继续保持 dirty；potato 的串行协调器按该规则实现。
- Huobao 把提示词文件作为生成、查看和编辑的同一来源；potato 因此前移默认系统提示词为后端唯一目录，并让画布检查器读取、编辑和恢复同一份默认值。
- ComfyUI 由节点定义驱动菜单、画布和参数面板；potato 的生产角色目录同样是创建工具、默认模板、节点卡片与检查器语义的唯一来源，不再维护多套节点枚举。
- AICON 明确区分稳定资产、分镜关键帧和镜头视频；potato 采用“材料 + 生产用途 + 资产分类”合同表达同一核心链，不引入其大型 Agent 或队列体系。

## 明确不照搬

- 不采用 Huobao 的固定阶段表单和左侧进度轨，本产品保持纯画布主体验。
- 不引入 ComfyUI 的大型扩展、队列、模型管理和多标签架构，只吸收选择与运行反馈。
- 不引入 tldraw SDK 或其许可约束，继续使用已经确定的 React Flow。
- 不复制 AICON 的旧 JavaScript/Vue 实现、Assistant 侧栏或整图/节点双持久化模式。
- 不引入 CRDT、实时多人同步或浏览器本地数据库；当前产品是本地 Node 服务的单用户工作台，服务端 optimistic revision 已足够阻止旧页面覆盖。
- 不使用任何单边彩色竖条、状态 rail、`border-left`、`border-right` 或伪元素侧边强调。
- 不复制参考项目源码、品牌、素材或视觉皮肤；potato 保持自己的 TypeScript 架构与视觉语言。
